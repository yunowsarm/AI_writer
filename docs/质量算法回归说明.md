# 质量算法 2.0 回归说明

## 实际记录与可复现缺陷

只读核对已有记录：同一剧本最近两次完整报告为 77→71 分，正文 52,455→62,136 字，问题 264→232 条。问题条数下降不能直接证明内容更好，也不能解释全部降分；因此没有改动历史分数或回退真实正文。

可复现的旧缺陷有三项：模型自由分数会直接改变总分；改稿未经过改善复核即可应用；整集时长偏差定位到首段并触发改写。新测试分别在旧实现中失败后修复。

## 新逻辑

```text
保存快照 → 证据分析与可复用块缓存 → 引用校验
→ 分集等权、固定严重度、同位置取最大扣分 → 可展开的扣分依据
→ 合并同段意见 → 最小改写 → 角色/格式/新重复检查
→ 同集分批双向对比 → 整集衔接双向对比
→ 推荐 / 待人工确认 / 保留原稿 → 作者选择 → 事务应用与版本备份
→ 当前稿重新评估，同标准报告才比较分数
```

具体公式见《多供应商与质量评估》，复核及接口见《质量评估一键优化》。新旧评分版本不直接比较。系统不设置分数下限，也不会自动将新分数改成不低于上次；真正出现新问题仍应反映到评分。

## 验证方法与边界

- `node --test server/test/quality-regression.test.js`：固定证据计分、提示排除、篇幅权重、扣分单调性与比较顺序偏差。
- `node --test server/test/personal-ai.test.js`：通过真实 Express/MySQL 接口验证候选退步拦截、接口防绕过、人工确认、局部通过但整集退步、81 处批量处理，以及评估→优化→应用→再次评估闭环。
- 测试仅使用 `mujian_test` 与本地模拟模型，不消耗真实 Key，不修改真实剧本。
- `QA_REVIEW_STATES=1 node tools/quality-ui-check.mjs` 提供三种复核状态的界面验收样例。PowerShell 设置环境变量需使用 `$env:QA_REVIEW_STATES='1'`。

自动化验证证明流程与计分规则正确，不等同于验证实际模型的文学评审准确率。后续人工标注集可以用来校准严重度与扣分值；当前权重与扣分均为公开的工程规则。temperature=0 与双向比较仍不能消除模型随机性、遗漏或偏好。
