# 邮箱验证流程

## 本次变化

原注册接口在 SMTP 未配置时会降级为免验证码注册，前端同时隐藏验证码输入。本次删除此分支：普通用户注册必须完成邮箱验证，不完整配置返回 `503 EMAIL_NOT_CONFIGURED`。

注册页面分为两步：填写昵称、邮箱和密码，点击下一步进入验证邮箱，获取验证码并确认。第二步开始前不创建账号，返回修改邮箱后需要使用对应邮箱的验证码。服务端在同一事务内消费验证码、创建账号并写入验证时间，然后建立登录会话。

已有账号不自动标记已验证，也不强制退出；可在个人中心看到未验证状态并补验。验证码登录、验证码重置密码和兼容的邮件重置链接成功后也会记录验证时间。管理员初始化及第三方身份创建独立于普通邮箱注册，不伪造邮箱验证状态。

## 数据和接口

- 用户新增 `email_verified_at DATETIME NULL`。旧数据为空，新注册成功写入 UTC 时间。`publicUser` 返回 `emailVerified` 和 `emailVerifiedAt`，不返回验证码或密钥。
- `POST /api/auth/email-code`：参数 `{email,purpose}`，用途为 `register/login/reset/verify`。`verify` 要求登录且邮箱与当前账号一致；注册用途要求邮箱未注册，登录和找回用途要求账号存在且启用。
- `POST /api/auth/register`：参数 `{email,password,nickname,code}`，必须使用注册用途的六位验证码。
- `POST /api/auth/email-verify`：参数 `{code}`，要求登录，只验证当前账号邮箱，不能验证或更换他人邮箱。
- `POST /api/auth/email-login`、`POST /api/auth/email-reset` 保持原参数，用途独立校验。
- `GET /api/auth/capabilities`：`emailCode` 表示邮件服务配置完整；`registrationRequiresEmail` 固定为 `true`。

验证码十分钟有效，六十秒发送冷却，单次消费，错误五次后失效。摘要保存，不在日志或响应打印验证码。邮件发送失败或 SMTP 拒绝收件人时清理本次凭据并返回明确错误，不展示成功提示。前端按邮箱和用途分别倒计时，切换用途时清空输入，不能复用旧验证码。

## 在另一台电脑升级

先停止项目服务，进入该电脑实际项目目录，执行：

```powershell
git pull origin main
npm ci
npm run migrate -w server
npm run dev
```

保留 `.env` 和 `.local`，无需重新 `setup`。迁移增加字段，不清空账号或作品。若通过 `npm start` 运行构建页面，还需先执行 `npm run build`。

在该电脑 `.env` 填入有效的 `SMTP_HOST`、`SMTP_PORT`、`SMTP_SECURE`、`SMTP_USER`、`SMTP_PASSWORD`、`SMTP_FROM`。QQ 邮箱使用 SMTP 授权码，不使用邮箱账号密码；完整配置后重启后端。不要将实际授权码提交 Git。

## 验证范围

独立测试库覆盖：未配置邮件拒绝注册、缺失及错误验证码、冷却、成功创建已验证账号、验证码消费、旧账号补验权限、过期、五次错误锁定、用途隔离、登录和重置更新验证状态、密码重置撤销旧会话，以及邮件服务器拒收处理。测试仅模拟邮件服务，真实邮件投递需在部署电脑配置 SMTP 后进行。

页面验收检查注册两步跳转、未填写验证码的阻止提示；未向外部邮箱发送邮件。前端构建独立检查。运行测试前需准备 `mujian_test` 数据库及相应权限。
