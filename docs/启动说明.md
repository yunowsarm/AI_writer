# 启动说明

## 运行条件

- Node.js 22 LTS 或更高版本，以及随附的 npm。
- MySQL 8.0。数据库服务与 Node.js 都需要安装，源码不会自带这些软件。
- 首次安装依赖需要联网；使用 AI 功能时后端需要访问所配置的模型服务。
- 在包含 `package.json` 的项目根目录执行下方命令。

默认地址：前端 `http://127.0.0.1:3003`，后端 `http://127.0.0.1:31001`。

## 方式一：Windows 独立数据库，推荐本地毕业设计演示

此方式为项目单独创建数据库实例，不使用其他项目的数据库，监听 `127.0.0.1:3308`。先确认 3308 端口没有被其他服务占用。

默认 MySQL 程序路径为 `C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqld.exe`。如果安装在其他目录，在 PowerShell 中设置实际路径（每次启动前均需设置，或设置为系统用户环境变量）：

```powershell
$env:MYSQLD_PATH = 'D:\MySQL\bin\mysqld.exe'
```

首次运行：

```powershell
npm ci
npm run setup
npm run dev
```

`setup` 会生成本机 `.env`、数据库随机密码、`mujian` 与 `mujian_test` 数据库、表结构、官方模板和初始管理员。管理员账号密码见本机 `.local/首次登录.txt`，首次登录后修改密码。

打开 `http://127.0.0.1:3003`。以后双击 `启动系统.cmd` 即可，或执行 `npm run dev`。关闭启动窗口或按 Ctrl+C 停止前后端；需要关闭项目独立数据库时使用 `停止项目数据库.cmd`。

中文项目路径下工具可能建立 M: 等空闲盘符映射，实际数据仍保存在项目 `.local` 中，不要删除其中的数据。不要在使用已有 MySQL 的方式下运行 `setup`。

## 方式二：使用已安装并运行的 MySQL

适用于使用已有数据库的 Windows、Linux 或 macOS。先安装依赖并复制配置：

```powershell
npm ci
Copy-Item .env.example .env
```

Linux / macOS 使用 `cp .env.example .env`。如果已经存在 `.env`，直接编辑，勿用示例覆盖已有密码。

由数据库管理员在 MySQL 中创建专用数据库与账号，以下口令必须替换为自己的强密码：

```sql
CREATE DATABASE mujian CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'mujian'@'127.0.0.1' IDENTIFIED BY '请替换为自己的数据库强密码';
GRANT ALL PRIVILEGES ON mujian.* TO 'mujian'@'127.0.0.1';
```

上例为 MySQL 与后端在同一台电脑、后端通过 `127.0.0.1` 连接。数据库在另一台机器时，应按实际后端来源地址授权，并调整网络访问配置。

编辑项目根目录 `.env`：

```dotenv
PORT=31001
HOST=127.0.0.1
APP_ORIGIN=http://127.0.0.1:3003
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=mujian
DB_USER=mujian
DB_PASSWORD=填写刚才设置的数据库密码
ADMIN_EMAIL=填写自己的管理员邮箱
ADMIN_PASSWORD=填写自己的初始管理员强密码
NODE_ENV=development
```

`DB_PORT` 必须填写实际数据库监听端口。然后创建表、初始模板和管理员并启动：

```powershell
npm run migrate -w server
npm run dev
```

迁移只在管理员邮箱尚未存在时创建管理员，不会修改已有管理员密码。此方式无自动生成的首次登录文件，使用自己填写的管理员账号登录。日常保持 MySQL 服务运行，再执行 `npm run dev`。

## AI、邮箱与扫码登录

- 每位用户登录后在左侧“API 配置”中添加供应商、Base URL、API 格式、API Key 和模型；启用供应商与模型后，创作时选择模型。密钥保存在后端数据库中，不放在前端配置。
- 邮箱验证码按根目录 `.env.example` 填写 SMTP 参数。例如 QQ 邮箱使用 `smtp.qq.com`、465、`SMTP_SECURE=true`，`SMTP_USER` 与 `SMTP_FROM` 填完整 QQ 邮箱地址，`SMTP_PASSWORD` 填邮箱服务授权码。
- 微信登录需自行申请网站应用，填写 `WECHAT_APP_ID`、`WECHAT_APP_SECRET` 与 `WECHAT_CALLBACK`。未配置时入口不可用。
- 开发扫码演示为独立演示功能，不代表真实微信身份，详见 [演示扫码登录](演示扫码登录.md)。生产环境禁用。

## 构建后由后端统一提供页面

在数据库配置完成并已迁移后运行：

```powershell
npm run build
```

将 `.env` 的 `APP_ORIGIN` 改为实际访问地址。本机体验构建版本时可设为 `http://127.0.0.1:31001`，然后：

```powershell
npm start
```

打开 `http://127.0.0.1:31001`。公网部署应使用 HTTPS、`NODE_ENV=production` 与实际域名 `APP_ORIGIN`，通过反向代理转发至后端。修改域名后也要同步第三方登录回调。

## 端口与排错

- 前端端口 3003 已在 `web/vite.config.js`、`web/package.json`、`tools/dev.mjs` 中固定。更改它时还需同步 `.env` 的 `APP_ORIGIN`。
- 后端端口由 `.env` 的 `PORT` 控制；更改后需同步 `web/vite.config.js` 的 `/api` 代理地址及第三方登录回调。
- `ECONNREFUSED`：检查 MySQL 是否运行，及 `DB_HOST` / `DB_PORT` 是否匹配。
- “不允许的请求来源”：浏览器地址与 `APP_ORIGIN` 应一致，修改后重启后端。
- 端口被占用：先确认进程归属，再停止自己的旧服务，避免关闭其他项目。

PowerShell 查看监听端口与进程号：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 3003,31001 |
  Select-Object LocalAddress, LocalPort, OwningProcess
```

确认对应进程确实可以停止后，执行 `Stop-Process -Id 实际进程号`。

## 数据与源码备份

GitHub 不包含 `.env`、`.local/`、依赖、构建产物、本地截图、测试日志与附件。新电脑从空数据库开始。需要迁移已有账号和作品时，请单独安全备份并导入 MySQL 数据，同时保留 `.local/ai-master.key`，否则无法解密已有个人 API 密钥。勿将这些文件上传仓库。
