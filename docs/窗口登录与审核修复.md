# 窗口登录与内容审核修复

## 窗口登录

- 当前窗口在 sessionStorage 保存随机窗口编号，刷新沿用。新窗口独立初始化；复制窗口继承初始编号时，再次登录会生成新编号，避免切换账号覆盖原窗口。
- 每个窗口编号对应独立 HttpOnly 会话 Cookie，数据库仍只保存认证令牌摘要。前端不保存密码、API Key 或认证令牌。
- JSON、后台任务、SSE 和导出统一携带 `X-Window-Session`。有该标识时不回退旧共享 Cookie，失效会话不能串到另一个账号。
- 注册、登录、退出、修改密码与微信跳转同步使用窗口作用域。修改密码仍按原设计撤销该账号全部旧会话。
- 微信授权用 state 对应的短期 HttpOnly Cookie 带回窗口编号；不把认证令牌放进 URL。未配置真实微信应用时只能验证作用域路由逻辑。
- 升级后现有浏览器页面需要重新登录一次。没有窗口标识的旧接口客户端保留原 Cookie 兼容方式；网页新版始终携带窗口编号。

## 内容审核

已在实际数据库只读复现 `ER_OUT_OF_SORTMEMORY`：原查询把 `snapshot_json` 一起排序。现改为先查询分页编号，再按编号读取冻结快照并在应用层恢复顺序，不改动原稿、审核状态或公开版本。

## 验证

独立 `mujian_test` 中覆盖大快照列表、状态筛选、分页顺序、共享 Cookie 多窗口鉴权、权限隔离、刷新、复制窗口后切换与独立退出。测试数据只清理本次随机账号。`window-session.test.js` 直接运行真实前端作用域模块，校验 sessionStorage 行为。
