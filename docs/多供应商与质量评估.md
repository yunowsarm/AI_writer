# 多供应商 API 与剧本质量评估

## 使用入口

1. 左侧“API 配置”新增供应商：名称、baseURL、API 格式、API Key、请求超时、模型列表。
2. 供应商和各个模型分别启停；供应商停用时，其下全部模型不可调用。
3. “AI 剧本创作”的“生成模型”按供应商分组选择。继续生成时也可重新选择模型。
4. 编辑器“灵感助手”可单独选择改写模型。
5. 编辑器顶部“质量评估”选择评审模型后，评估整部已保存剧本。
6. 报告中点击“定位原文”跳到相应分集和选区；点击“按建议生成修改候选”进入助手预览，确认后才替换并保存新版本。

密钥按用户加密保存，页面只接收配置状态。空 Key 保留当前供应商原值；改变地址必须重新填写 Key。旧版个人 DeepSeek 配置首次读取时迁为默认供应商。

## API 格式

支持 OpenAI Chat Completions 兼容格式与 Anthropic Messages 格式。baseURL 填到服务版本根路径，例如 `https://api.example.com/v1`，调用时分别追加 `/chat/completions` 或 `/messages`，测试连接追加 `/models`。

供应商不提供模型列表接口时，可以手动添加准确的模型 ID。模型名称是展示字段，实际请求使用模型 ID。两种协议均解析流式正文和上游实际用量，不展示思考过程。

供应商地址使用公开 HTTPS 域名。网络边界拒绝私网地址和重定向，并固定 DNS 解析结果以防止重新解析到内网。

协议参考：[OpenAI Chat](https://developers.openai.com/api/reference/resources/chat)、[Anthropic Streaming](https://platform.claude.com/docs/en/build-with-claude/streaming)。

## 算法流程与职责

算法版本：`quality-2.0`，量表 `evidence-2.0`。AI 提取有原文证据的问题，程序按固定扣分表计算；不采用模型自由分数，不按改写后的篇幅重新分配权重。分数表示本次检测到的缺陷情况，尚未经过人工标注集校准，不代表艺术水平或商业效果。

```text
保存当前编辑内容
→ 事务读取剧本快照
→ SHA-256 内容指纹与完整报告缓存检查
→ 集 / 场景 / 段落解析与稳定位置索引
→ 格式、集数、篇幅、内部重复规则检测
→ 按段落分块逐段语义分析，记录人物事实和事件
→ 对全剧事实与事件时间线进行一致性检查
→ 校验原文证据、问题去重、低置信标记
→ 固定证据扣分、同位置取最大值、分集等权汇总
→ 保存报告、展示图表和建议
→ 最小修改候选、双向比较、整集衔接复核、作者确认应用
```

### 本地算法

- 每集非空行分配稳定段落 ID，记录场景号与原文字偏移；超长行每 1200 字拆段。
- 正文块按约 7000 字划分，最多 160 块。超过容量明确拒绝，不截断后伪称完成。
- 内部重复检测去除空白、标点和符号，提取字符三元组；利用倒排索引筛选候选，再计算 Jaccard 集合相似度。
- Jaccard(A,B) = |A∩B| / |A∪B|；至少 24 字且相似度不低于 0.85 时提示内部重复。为控制长文本开销，只复核最相关的 40 个候选，高频三元组索引保留最近 100 项。因此这是有界候选检测，不能保证发现所有重复。
- 场景、角色台词、动作或旁白使用明确标记规则识别。
- 时长按每分钟约 240 字粗估，低于目标一半或超过目标两倍时提示检查；实际拍摄时长受语速、动作、停顿和剪辑影响。

### AI 语义评审

每块返回摘要、角色属性与状态事实、关键事件、冲突/反转/悬念强度及有引用的问题。兼容旧响应中的 `scores`，但不采用它计算总分。前面最近三块摘要和事实参与当前块分析，全剧事实与事件再统一核对一次。

状态事实包含角色、属性、值、剧情时序、原文 ID 和逐字引用。跨集检查要求考虑撒谎、梦境、回忆、身份揭露、时间跳转等解释，并至少提供两处不同原文证据。事实链的语义判断由所选模型完成，服务端不声称用简单关键词就能判定人物矛盾。

模型返回严格通过 Zod 字段与范围校验。格式错误最多重新请求一次，每次真实请求均记入用量。问题引用必须在指定段落原文中逐字存在；无效引用问题被过滤。置信度低于 0.7 标为待作者确认，不计分。时长、计划集数、创作偏好标为 `advisory`，仅提示，不扣分、不自动改写。

评审与复核使用 temperature=0，改写使用 0.2；低温不能保证模型完全确定。相同内容、量表及供应商配置复用完整报告；若只改动部分正文，则对完整评审输入（正文、资料、上文摘要与事实）计算块指纹，只复用输入完全一致的分析。保存 revision 自增不再单独使内容指纹失效。

### 评分公式

| 维度       | 权重 | 计算                                     |
| ---------- | ---- | ---------------------------------------- |
| 人物一致性 | 25%  | 根据人物维度的有效证据扣分               |
| 情节连贯性 | 25%  | 根据情节维度的有效证据扣分               |
| 节奏与冲突 | 20%  | 根据节奏缺陷扣分；冲突强度曲线只作描述   |
| 台词表现   | 15%  | 根据台词与重复段落证据扣分               |
| 格式与约束 | 15%  | 根据可定位格式缺陷扣分；篇幅和集数仅提示 |

每集每维基础分 100。问题严重度为轻微 2、较重要 6、严重 12；同一问题在同集有 n 个证据位置时，每位置分摊为 points/n。同维度同位置取各问题分摊值的最大值，规则和模型不叠加扣除。该集维度分 = max(0,100 − 各位置扣分之和)，再对所有分集等权取平均并四舍五入。解决一个问题不会因“扣分组拆开”而增加其余扣分，扩写也不会改变分集权重。

综合分 = round(人物 × 0.25 + 情节 × 0.25 + 节奏 × 0.20 + 台词 × 0.15 + 格式 × 0.15)。

任何必要分块或全剧一致性检查未完成时，只保存部分结果，不产生综合分。每个扣分位置及关联问题均保存在 `result.scoring.deductions`，页面可展开查看。报告保存输入快照；后续修改不覆盖历史。比较分数要求同算法、同量表、同供应商 ID/地址/格式/模型；旧版自由评分与新版不直接比较。相同有效问题保证计分一致；模型对新内容提取的问题仍可能变化，不承诺每次优化后的总分必涨。

## 接口

以下接口均要求登录，归属取自会话，不接受客户端指定其他用户。

| 方法   | 路径（带 /api 前缀）          | 用途                                              |
| ------ | ----------------------------- | ------------------------------------------------- |
| GET    | /me/settings/providers        | 本人供应商及模型清单，不含 Key                    |
| POST   | /me/settings/providers        | 新增供应商                                        |
| PUT    | /me/settings/providers/:id    | 更新供应商、模型及启停状态                        |
| DELETE | /me/settings/providers/:id    | 删除本人供应商，保留历史用量                      |
| POST   | /me/settings/providers/test   | 测试草稿或已存供应商的模型列表                    |
| POST   | /ai/generate                  | 原生成接口增加 selection                          |
| POST   | /ai/rewrite                   | 原改写接口增加 selection                          |
| POST   | /quality/scripts/:id/evaluate | SSE 评估：start/report/phase/done/error/cancelled |
| GET    | /quality/scripts/:id/reports  | 最近 30 份报告摘要及过期标记                      |
| GET    | /quality/reports/:id          | 本人报告结果、快照与过期状态                      |
| POST   | /ai/jobs/:id/cancel           | 取消本人生成、改写或评估任务                      |

`selection` 示例：`{ "providerId": 1, "model": "供应商的准确模型ID" }`。

供应商保存字段为 `name/baseUrl/apiFormat/apiKey/enabled/timeout/models`；其中 `models` 是 `{model,label,enabled}` 数组。`apiFormat` 为 `openai-chat` 或 `anthropic-messages`。`timeout` 单位毫秒，范围 10000～600000。单人最多 20 个供应商、每供应商最多 100 个模型，模型 ID 不可重复。

质量任务沿用每人一个活动任务及每小时 30 个 AI 任务限额；任务启动时固定供应商配置快照。每次评审、结构重试和最终一致性检查均记录实际 Token、供应商、模型、阶段及耗时。费用仅在已知官方计价来源和缓存用量完整时估算，不套用到第三方供应商。

## 数据与升级

新增 `ai_providers`、`ai_provider_models`、`quality_reports`；`ai_requests` 增加供应商来源快照和评估阶段。部署旧数据库后先执行：

```sh
npm run migrate -w server
npm run build
```

再启动后端。已有个人 Key 不会被分配给其他账号，现有剧本、版本、社区关系和用量记录保留。

## 验证

`npm test`：独立 `mujian_test` 数据库和本地模拟模型，覆盖账号隔离、选择模型与密钥路由、启停、缓存与过期、结构失败、实际用量、两种协议及算法边界。

`node tools/quality-ui-check.mjs`：在 5191 端口启动隔离样例，打开输出的验收地址。使用本地模拟响应，不能用于衡量真实模型的评审质量。验收后对 `/__quality_check_stop` 发 POST 结束服务并清理本次测试记录；不修改业务库。

真实供应商的网络、配额、模型权限以及具体模型的 JSON 遵循能力，需要填入自己的配置后验证。自动化测试与 UI 验收均不消耗真实 Key。
