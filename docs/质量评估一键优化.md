# 质量评估一键优化

## 使用流程

1. 在剧本编辑器打开质量评估报告，点击“一键优化”。
2. 查看段落数、预计改写次数、预计复核次数、完全重复删除数及需确认事项，选择个人 API 模型。
3. 点击“开始一键优化”。合并同段落意见并作最小修改，进行局部与整集双向比较；可后台运行、停止或从任务中心找回。
4. 查看红绿差异与复核说明：通过的默认推荐，不一致的可逐项选择，也可通过“选择全部可应用候选（含待确认项）”全选；退步、未生成、无修改的条目不纳入全选。确认后统一提交选中修改。
5. 在版本记录中对比或恢复原稿。应用不伪造质量分数，需重新评估当前稿件后更新分数。

## 执行规则

- 针对整份报告的未处理位置，不受面板当前维度筛选影响。
- 同段意见合并为一次调用；同集完全相同的重复段落保留前一处，其他匹配处生成删除候选。
- 时长与集数只作提示，不扣分、不自动改写首段。跨集人物或全剧一致性涉及事实取舍，交由作者选择修改的一侧。
- 改写带上题材、设定、大纲和目标前后的实际邻段，不再统一将片段“重新创作”为完整场景。
- 候选先检查角色、标记和新重复，再匿名交换 A/B 顺序比较两次；两次均认可改善、置信度至少 0.8 且无退步证据才推荐。随后对同集同时采用的候选再作两次整集衔接比较。
- 固定位置偏好、低置信、无实质改善、结构化结果失败或整集过长无法完整复核，均不默认采用。整集复核上下文超过 10 万字符时不截断后伪称通过，保留人工确认途径；字数本身没有应用硬限制。
- 跨集重复、相似但不相同、低置信度、原文改动或位置不明确的事项列为待确认，不直接删除。
- 只修改命中的富文本块，其他段落的标题、粗体、斜体和列表保留；篇幅只作参考。
- 生成候选期间不改正文。停止或部分失败仍保留已完成结果，可选择应用。
- 不限制单次优化的段落数量；生成候选与统一应用均支持超过 80 处，按实际完成位置更新进度。

## 数据与接口

- `GET /api/quality/reports/:id/optimization-plan`：读取计划及指纹，不调用模型。
- `POST /api/quality/reports/:id/optimize`：后台生成，提交计划指纹及个人模型选择。
- `GET /api/quality/optimizations/:jobId`：查询本人候选和应用状态。
- `POST /api/quality/optimizations/:jobId/apply`：提交勾选的 `changeIds`；人工确认候选同时提交 `acknowledgedReviewIds`。被判退步的候选不可通过该接口应用。

任务和候选复用现有 `ai_jobs`，真实模型调用进入用量记录。所有接口校验本人归属，应用时锁定任务及受影响分集并核对版本；任一分集有新修改则整批拒绝，不覆盖用户编辑。重复提交不会重复生成版本。

复核阶段为 `verification`，在 AI 用量页面显示为“优化候选复核”。预计次数 = 改写分批数×2 + 有改写的分集数×2；实际随候选长度、失败与格式重试变化。复核使用当前选择的模型，不是独立人工评审，不保证艺术质量或未来评分一定上涨。旧版未复核的候选需重新生成，已应用历史不变。

应用前保存原稿备份，应用后新增版本。仅选中的位置更新处理状态，需作者确认的建议继续保留。

## 验证范围

- 意见合并、同集去重、跨集保留、过期证据跳过、HTML/JSON 未改动样式保留。
- 后台与停止、账号隔离、确认前正文不变、版本冲突、应用幂等。
- 模拟页面完成计划展示、候选勾选、跨页面和刷新后找回、统一应用及重载最新正文。
- 新增回归覆盖：自由分数波动、扩写权重偏移、提示误改、解决问题不增扣分、位置偏差、局部退步、整集退步、人工确认和优化后再次评估。

交换版本顺序用于降低 LLM 评审的位置偏差，依据 [Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena](https://arxiv.org/abs/2306.05685)。该策略不能消除模型偏差，页面仍保留人工确认和历史版本。

## 逐项问题验收（paired-2.0）

每个候选冻结原建议的唯一 issueId 清单。两次复核都必须逐项返回两版的 present/absent/uncertain；present 必须引用该版真实原文，缺项、重复或伪造引用均转人工确认。只有两次都确认“原版存在、候选已消除”，且未报告新增缺陷，才能自动推荐。

即使整体比较偏好候选，报告新增缺陷且置信度≥0.8也会保留原稿；低置信新增或原问题仍存在则转待确认。两次新增问题按维度与引用去重，页面分别展示本段与整集的目标数、已解决、仍存在、不确定、新增及原文依据。这些是本次目标复核统计，不能冒充全剧重新评估的问题总数。

手动采用待确认候选只表示正文已修改，不自动标记对应建议已解决；重新评估后确认。旧 paired-1.0 未应用候选需重新生成，已应用历史保留。此次扩展复用现有双向比较调用，不额外增加调用轮数，但结构化输出更多，可能增加输出 Token 或重试。

复核仍由模型完成，独立重评可能发现原先漏检的问题。因此系统不承诺所有后续报告的问题总数严格下降，不隐藏有效问题，也不为减少条数而删减报告。
